# R1/R2 Master｜足球單雙正式封存

> 用途：供其他 ChatGPT 對話／工作流程直接讀取目前正式封存的單雙 R1/R2。
> 規則：新一輪或新盤口版本只可「追加新版本」，不得覆蓋舊版本；對答案時依賽前已封存版本核對。

## 讀取規則

- `LATEST_OFFICIAL` = 本檔最後新增的正式封存版本。
- `LATEST_BY_LEAGUE` = 各聯賽目前最新正式版本；跨對話讀取時優先依聯賽使用此索引。
- R1 / R2 為每輪固定兩場單雙精選。
- **自 2026-10-20 起新增 R3**：1X2、全場大小2.5、全場單雙三個市場每輪都固定封存 **R1 / R2 / R3**；R3 為第三順位正式精選，必須像 R1/R2 一樣賽前封存、賽後獨立結算與累計命中率。歷史輪次不得事後補 R3。
- 「單」= 全場總進球為奇數；「雙」= 全場總進球為偶數。
- `方向強度分數` 是模型相對強度／排序分數，不等同校準後的真實命中機率。
- 若後續有臨場版，必須新增獨立版本（例如 `2026-10-10_LIVE`），不得改寫本檔既有封存內容。
- 若賽果已出，追加實際比分、實際單雙、命中/未中，不得修改原預測。
- 每次新一輪正式封存必須同步記錄截至上一輪的嚴格前推 R1 勝率、R2 勝率、R1+R2 合計勝率與樣本數；這些是已發生的前推實績，不等同新一場的真實命中概率。
- **盤口移動永久追蹤規則（自 2026-10-19 起）**：每輪正式預測必須同時封存 `OPEN/OPENPROXY` 與 `PRE-KICK` 兩個盤口快照；不得以終盤回填初盤。至少記錄 Bet365 1X2（主/和/客）、O/U2.5（大/小）、亞洲盤 AH（讓球線與兩邊賠率），並計算去水後機率。
- `PRE-KICK` 以開賽前約 **60 分鐘（容許 ±30 分鐘）** 為標準；若可取得，可額外保存 T-24h／T-6h 中間快照，但 OPEN 與 PRE-KICK 為必填。
- 每場必須計算盤口變化：`ΔP_1X2`、`ΔP_Over2.5`、`ΔP_AH` 與 AH 線位變化；同模型方向移動 ≥3 個百分點標 `Market Confirm`，反向 ≥3pp 標 `Market Against`，≥5pp 標 `Strong Confirm/Against`；亞洲盤若跨 ≥0.25 球亦另標 `Line Move`。
- 賽後除原有 1X2／大小2.5／單雙對答案外，必須追加「盤口移動 vs 賽果」欄位，分別統計 Confirm／Against／Neutral 的命中率；這只記錄**關聯與預測價值**，不得直接宣稱盤口移動造成賽果。
- R1/R2 必須另行保存 OPEN→PRE-KICK 的盤口變化與是否仍維持正式方向；若臨場盤改變模型判斷，只能建立新的 `LIVE/PREKICK` Record，不得覆蓋原 OPEN Record。
- **五大聯賽統一固定格式（自 2026-10-19 起）**：英超 EPL、西甲 LaLiga、德甲 Bundesliga、義甲 Serie A、法甲 Ligue 1 後續每一輪一律採同一流程：`初盤 OPEN/OPENPROXY 封存 → 賽前模型預測與 R1/R2/R3 封存 → PRE-KICK 臨場盤快照 → 計算盤口變化/市場確認或反向 → 若需要另建 PREKICK/LIVE 版本 → 賽後核對 1X2 / O-U2.5 / 單雙 → 統計盤口移動與賽果關聯 → 更新各聯賽 R1、R2、R3、R1+R2+R3 嚴格前推勝率`。
- 五大聯賽每輪必須保留三層紀錄：**A. 初盤版**（正式原始前推，不得回改）、**B. 臨場版**（若模型/排序改變，另開 Record）、**C. 賽後結算版**（只追加結果與統計）。
- 五大聯賽的盤口影響統計要分市場保存：1X2、O/U2.5、AH 與三市場 R1/R2/R3；至少累積到足夠樣本後再判斷 `Market Confirm/Against` 是否具有可泛化預測價值，禁止因單輪輸贏直接改閾值。
- 各聯賽仍保留自己的主模型與 selector；統一的是**資料封存、盤口追蹤、臨場比較、賽後審計流程**，不是把五大聯賽模型參數硬做成一樣。

- 正式 R1/R2 追蹤（GW2–GW9）：R1 **5/8=62.5%**；R2 **6/8=75.0%**；R1+R2 **11/16=68.75%**。
- 樣本仍小；68.75% 僅是目前已發生前推實績，不視為穩定真實勝率。

### 關鍵診斷
1. **底層方向並非完全失效，排序層問題更大**：R2 長期高於 R1，顯示「最高方向強度=最可靠」未被證明。
2. **極端方向偏斜必須當作模型異常訊號**：GW9 產生 9單1雙，但實際3單7雙；此類輸出不可直接照單全收。
3. **比分錨點污染單雙**：2-1、1-2、1-0 等錨點會機械性推向單；一球誤差即可讓單雙翻向，因此比分只能作低權重輔助。
4. **O/U 與單雙必須去相關**：大球不代表單，小球也不代表雙；禁止把 O/U 方向直接轉成 parity 加分。
5. **streak / mean-reversion 不應作主訊號**：近期連單或連雙後抓反轉，缺乏足夠前推證據，只保留低權重。

### 建議版本：EPL Parity Selector V2（研究版，尚未取代正式模型）
- Base：主客隊近期單雙率、主客拆分、總進球分布；全部做小樣本收縮。
- Independence：比分錨點、O/U、市場熱門方向不得直接決定單雙，只作輔助或風控。
- Ranking：R 位需至少兩個獨立訊號同向；不再單純按 abs(P單-0.5) 排名。
- `PARITY_SKEW_ALERT`：同一輪若單或雙 >=7/10，強制二次審計；>=8/10 時不得直接封存精選，除非有額外獨立證據。
- R1/R2：下一輪研究優先保留 R2 路線；R1 若沒有明顯獨立共振可降級或 PASS。
- R3：研究階段允許 PASS，不為湊滿三場而出手。
- 評估：至少再累積 4–6 輪 live-forward 後，才決定 V2 是否升為正式 selector；禁止用單一輪結果調參。

### 暫定操作結論
- 全輪10場仍照規則輸出並封存，供模型審計。
- 真正下注層優先只認 R1/R2；R3 可 PASS。
- 當 `PARITY_SKEW_ALERT` 觸發時，下注層減碼或只留一場最強共振，不追整輪同方向。

## Critical Audit｜LIGUE1-PARITY-20261104｜單雙極度檢討／Forced R1-R2 停用為投注依據

- 審計日期：2026-11-04
- 審計對象：`法甲專用 R80 V2 DrawGuard` 的全場單雙底層方向、每輪 Forced R1/R2 排名、正式稀疏 selector，以及 2026–27 GW5–GW9 live-forward。

### A. 核心發現：Forced R1/R2 歷史上本來就沒有優勢

依 V2 封存資料，將每輪所有比賽按 `abs(Parity_ProbOdd - 0.5)` 由高到低硬排前二：

| 區段 | Forced R1 | Forced R2 | R1+R2 |

=> 結論：`Parity_R1_R2 = descending abs(Parity_ProbOdd-0.5)` 只應視為**相對排序／shadow research**；不得再把它當正式投注 selector，也不得引用 V1 正式 selector 的80%級歷史成績替它背書。

### B. 底層 `Parity_ProbOdd` 本身辨識力很弱

封存歷史資料重新審計：

- Development OOF：全場方向 668/1372 = **48.7%**；AUC 約 **0.492**；`Parity_ProbOdd` 標準差只有約 **0.0057**。
- 2025-26 Validation：全場方向 170/306 = **55.6%**；AUC 約 **0.533**；標準差約 **0.0060**。
- Forced R1/R2 的典型 edge 只有約 **0.5～1.5pp**，代表 50.8%、51.5% 這類數值不能解讀成真正有明顯勝率差。

結構原因：12-component S-XOR 經多視窗／先驗平均後會強烈收縮到 0.5 附近；拿極小的偏離值強制排名，容易把估計雜訊放大成 R1/R2。

### C. 真正歷史有效的是「正式稀疏 selector」，不是 Forced R1/R2

- Odd：`drawp <= 0.2181925054 AND lg_odd150 >= 0.54375 AND lg_odd50 >= 0.5666666667` → 正式方向 **單**。
